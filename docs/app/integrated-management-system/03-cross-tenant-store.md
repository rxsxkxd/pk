# テナント横断の検索・集計用ストア

> [02-architecture-direction.md](02-architecture-direction.md) のパターン C の詳細。選択肢の絞り込みは Q2（鮮度）と Q4（データ量）の回答待ち。

## 目的

- テナント横断の検索・集計を、**1 本の SQL** で実行できるようにする。
- 横断の処理でテナント DB（本番の OLTP）に負荷をかけない。
- ライセンス情報との JOIN を、同じストアの中で行えるようにする。

## データモデル

- 行動履歴は全テナント分を 1 つのテーブルにまとめ、**`tenant_id` 列を追加**する。
- テナント DB 側のテーブル名・列名はそのまま使い、変換は最小限にする。
- ライセンス DB のテーブルも同じストアに取り込む。
- テナントの一覧（`tenant_id`、DB の接続先、状態）を管理するテーブルを用意し、取り込みの対象もこれで管理する。

## 選択肢

| 選択肢 | 鮮度 | 運用負荷 | コスト感 | 向いている場面 |
|---|---|---|---|---|
| **① RDS for MySQL → Redshift の zero-ETL 統合** | 数秒〜数十秒 | 小（AWS のマネージド） | Redshift の費用がかかる（Serverless も可） | 鮮度が要り、運用を増やしたくない |
| **② DMS（CDC）→ S3 → Athena** | 数分 | 中（DMS タスク 200 本前後の管理） | 低〜中 | 鮮度は数分遅れで良く、費用を抑えたい |
| **③ 定期エクスポート → S3 → Athena** | 日次など | 小〜中（エクスポートのジョブを用意する） | 低 | 日次の集計やレポートが中心 |
| ④ 集約用の MySQL（レプリカの集約など） | 数秒〜 | 大 | 中 | 既存の SQL をほぼそのまま使いたい |

### ① zero-ETL 統合

- RDS for MySQL のデータが Redshift に自動で複製される。ETL のパイプラインを自前で持たなくてよい。
- 要確認:
  - 対応しているエンジンのバージョンとリージョン
  - 1 つの Redshift に統合できるソースの数の上限（200 前後のソースを集約できるか）
  - テナントごとにスキーマ（データベース）が分かれて届くため、`tenant_id` 付きの 1 テーブルにまとめるビューやマテリアライズドビューが必要になる
- 前提: ソース側でバイナリログを有効にし、`binlog_format=ROW` にする。

### ② DMS（CDC）→ S3 → Athena

- DMS がバイナリログを読み、変更を S3 に書き出す。Athena（必要なら Apache Iceberg のテーブル）で検索する。
- テナント数が多いため、**DMS タスクの数と配置**（1 タスクで複数スキーマを扱えるか、レプリケーションインスタンスの数）の設計が必要。
- 前提: ① と同じくバイナリログの設定と、自動バックアップの有効化（バイナリログの保持のため）。

### ③ 定期エクスポート → S3 → Athena

- RDS のスナップショットを S3 へエクスポートする機能（Parquet 形式）や、自前の抽出ジョブで日次に書き出す。
- 最も単純だが、鮮度は日次になる。
- まず ③ で始めて、鮮度の要求が出たら ① か ② に移す段階的な進め方もできる。

### ④ 集約用の MySQL

- 既存の SQL を流用しやすいが、200 ソースからの集約を自前で運用することになり、データ量が増えると MySQL では横断集計が遅くなる。**優先度は低い**。

## 決め方

```
Q2 鮮度
├─ 数秒〜数十秒が必要 → ①（上限などの要確認事項が解消できれば）
├─ 数分遅れで可       → ① または ②
└─ 日次で可           → ③ から始める
```

Q4 のデータ量が大きい（数億行以上）場合は、MySQL のまま横断集計を続ける選択肢（④や、現行の全 DB 巡回）は外す。

## 運用上の注意

- **テナントの追加・削除**のときに、取り込みの対象も追従させる手順を用意する。
- **スキーマ変更**（列の追加など）が取り込み先に反映されるかを、選択肢ごとに確認する。
- 横断ストアは**読み取り専用**とし、結果をテナント DB やライセンス DB へ戻す必要があるときはバッチ経由で書き戻す（[04](04-batch-design.md)）。
- 個人情報を含む場合は、取り込み先のアクセス権限と保持期間を決める。
