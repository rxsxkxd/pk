## 役割

中段の [`ami-publish/`](../ami-publish/README.md) が用意した起動テンプレートの新しいバージョン（新しい AMI を指す）を使って、本番などのインスタンスを起動・入れ替える。

## 現状

担当者が行う。Auto Scaling グループは利用していない。

- 起動テンプレートの名前は `<application_name>-<環境>`（例: `myapp-staging`）。最新のバージョンは、起動テンプレートのスタックの出力 `LaunchTemplateVersion`、または AMI 公開パイプラインの出力変数 `LAUNCH_TEMPLATE_VERSION` でわかる
- 起動テンプレートには UserData とサブネットを入れていない。起動時にサブネットなどを指定する
- 起動テンプレートは中段の CloudFormation スタックが管理している。起動テンプレートを直接変更しない（前のバージョンに戻すときは中段の `rollback` を使う）

## 将来の余地（Auto Scaling グループ）

Auto Scaling グループで複数台構成にする余地がある。その場合も、Auto Scaling グループは中段の起動テンプレートのスタックとは別のスタックに置く（中段のスタック更新が本番のインスタンスに波及しないようにするため）。

## フェーズ 2 で実現したいこと（概要）

- AMI と起動テンプレートの公開（フェーズ 1）とは連動せず、担当者が明示的に実行したときだけ構築・更新する
- サーバーごとに定義のパラメーターを用意し、CloudFormation で構成する
- 起動テンプレートは、フェーズ 1 のスタックが Export した ID を参照し、バージョンは担当者がデプロイコマンドで明示的に指定する
- バージョンを指定した起動テンプレートからのインスタンスの構築と、既存インスタンスのアップグレードまたは置き換え

詳細と、決定が必要なこと（P1〜P7）は [design.md](./design.md)。無停止で切り替える方式の候補は [ブルーグリーンによる無停止の切り替え（候補）](./blue-green-switching-candidate.md)。
