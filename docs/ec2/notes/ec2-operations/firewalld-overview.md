# 補足: firewalld とは何か（利点と、向いている場面）

> 位置付け: 備忘録。[暫定対応: OS（iptables ＋ ipset、または firewalld）](./access-restriction-os-firewall.md) で firewalld を第一の案にしなかった理由と、firewalld がどういう場面で生きるかを残す。資料からの整理で、動かして確かめてはいない。
>
> 作成日: 2026-10-28

## firewalld とは

サーバー全体のファイアウォールを、**止めずに、分かりやすい単位で管理する**ための仕組み。常駐するプロセス（`firewalld`）が、カーネルのファイアウォール（iptables、または nftables）のルールを代わりに組み立てて入れる。RHEL や Fedora の系統では標準のファイアウォールで、AL2 と AL2023 でもパッケージを入れれば使える（どちらも最初は入っていない）。

利点は、高機能さよりも**管理のしやすさ**にある。

## 利点

| 利点 | 内容 |
|---|---|
| ゾーンとサービスという単位 | 「信頼するネットワーク」「外向き」などのゾーンに、ネットワークの口や接続元を割り当て、ゾーンごとに「`http` と `https` を許可」のように名前で管理する。iptables のルールを 1 行ずつ並べるより読みやすい |
| 止めずに変えられる | 変更を差分で反映するので、今つながっている接続を切らずにルールを変えられる。昔の iptables のサービス（`iptables-services`）は、読み直しのたびに全ルールを消して入れ直していた |
| 今の設定と保存した設定 | 今だけ試して（`--permanent` なし）、よければ保存する、という使い方ができる。試した設定は読み直し（`--reload`）で元に戻る |
| 裏の仕組みを隠してくれる | 裏で使うのが iptables から nftables に変わっても、同じコマンドで扱える（RHEL 8 以降や AL2023 では nftables を使う） |
| ほかのソフトウェアとの連携 | D-Bus という仕組みで、ほかのソフトウェアがルールを足し引きできる（NetworkManager、仮想マシンやコンテナの管理など） |
| 管理の道具がそろっている | `firewall-cmd`、止めたまま設定する `firewall-offline-cmd`、画面での管理（Cockpit など）、Ansible のモジュール。複数のサーバーで同じ方針をそろえやすい |
| よく使う機能が用意されている | ipset、rich rule（接続元や記録を含む細かい条件）、アドレスの変換（masquerade）、ポートの転送、全遮断（panic mode）、拒否の記録 |

## 向いている場面と、向いていない場面

| 向いている | 向いていない |
|---|---|
| サーバーのファイアウォール全体を「受信は既定で拒否、必要なものだけ許可」で管理したい | 1 つのポートだけにルールを足したい |
| ネットワークの口が複数あり、口ごとに信頼の度合いが違う | ネットワークの口が 1 つ（EC2 の多く） |
| 開け閉めするサービスが多く、変更が頻繁 | 数千件の一覧を毎日入れ替える（読み直しが重い） |
| RHEL の系統の道具（Ansible など）で、多くのサーバーをそろえて管理している | 前段（セキュリティグループ）で、すでに大部分を絞っている |

## AWS では使われにくい理由

EC2 では、**セキュリティグループ**が「受信は既定で拒否、必要なものだけ許可」の役をすでに担っている。サーバーの中にもう 1 枚ファイアウォールを置く利点が小さいため、AL2 や AL2023 の AMI では firewalld が最初から有効になっていないと考えられる。

## 使うときの注意

| 注意 | 内容 |
|---|---|
| 起動した瞬間に全体が切り替わる | ゾーンで許可していないポートは、起動した瞬間にすべて閉じる（`public` ゾーンの既定で開いているのは SSH などだけ）。今開いているポートを洗い出し、`firewall-offline-cmd` で止めたまま許可を済ませてから起動する |
| 既存のルールを置き換える | 起動すると、それまでに手で入れた iptables のルールは firewalld のものに置き換わる。手で入れたルール（例: 暫定対応の `PORT_GUARD`）とは併用しない |
| 今の設定と保存した設定の取り違え | `--permanent` なしの変更は読み直しや再起動で消え、`--permanent` ありの変更は読み直すまで効かない。`--permanent` で変えてから `--reload` するのが確実 |
| 入れただけで起動時に有効になることがある | パッケージによっては、入れただけで「起動時に有効」になる（systemd の preset）。そうなると次の再起動で動き出してポートが閉じるので、入れた直後に `systemctl is-enabled firewalld` を見る |
| 止めるとすべて開く | 既定では、止めるとルールを片付けて、すべて受け付ける状態に戻る |
| 大きな一覧の更新 | ipset に数千件を入れ替えるときは、定義のファイル（`/etc/firewalld/ipsets/<名前>.xml`）を書き換えて `--reload` する形になり、全体の読み直しを伴う |

細かな手順と、入れて有効にするときの挙動は [暫定対応のドキュメント](./access-restriction-os-firewall.md) の「firewalld を使う場合」と「入れて有効にするとき」。

## 今回の判断

| 要件 | 選んだもの | 理由 |
|---|---|---|
| 特定のポートを国内だけに絞る（暫定対応） | **iptables ＋ ipset** | 対象のポートだけに効き、ほかのポートに影響しない。集合の中身を一瞬で入れ替えられる。外すのもルールを 1 つ消すだけ |
| （将来）全台で、受信を既定で拒否にそろえる | firewalld が候補 | ゾーンとサービスで全体を管理でき、Ansible などでそろえやすい。ただし、国の一覧を毎日入れ替える部分は工夫が要る |
