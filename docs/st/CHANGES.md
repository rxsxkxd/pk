# 要件定義
## 全体説明

スマートフォンで撮った証明書の画像を送ると、画像解析サーバーで確かめたうえでチケット（QR コード）を発行し、ブラウザに表示するシステムを新しく作った。

| 項目 | 内容 |
|---|---|
| 利用者の環境 | スマートフォンのブラウザ。iOS 13 以上 / Android 9 以上 |
| 構成 | 画面は SPA（Vue 3.5 + TypeScript）、API は Go（AWS Lambda、arm64）。画面と API は同じアドレス（CloudFront）で提供し、API は `/v1/` 以下（API Gateway → Lambda） |
| 画像解析 | 外部の画像解析サーバーに画像をそのまま送り、結果（`PASS` / `REJECT` / `RETRY`）を受け取る。発行の Lambda は VPC のプライベートサブネットに置き、NAT ゲートウェイ経由で解析サーバーにつなぐ |
| チケット | チケットコード `{日付8桁}{時刻6桁}{UUIDv4 のハイフンなし小文字16進32桁}{固定文字列}`（日時は日本時間）と、その署名（HMAC）。API はチケットを保存しない |
| 画像の上限 | 4MiB（4,194,304 バイト）。超えた写真は、画面で縮めてから送る |

# 機能設計
## 各機能ごと

### 1-1. 目的

- 利用者が、手持ちのスマートフォンで撮った証明書の画像だけで、その場でチケットを受け取れるようにする
- 証明書の確認は画像解析サーバーに任せ、結果が `PASS` のときだけチケットを発行する
- 発行したチケットは、QR コードとして画面に出し、同じ URL を開けば何度でも表示できるようにする

### 1-2. 背景

- 利用者の端末は古いものも含む（iOS 13 / Android 9）。古いブラウザでも動く作りにする必要がある
- スマートフォンの写真は大きく（高画素の端末では 4MB を超える）、そのままでは API の上限（Lambda の受け取れる大きさで決まる）を超えることがある
- 発行の記録を持つデータベースは置かない。チケットの正しさは、コードの署名で確かめる

### チケット発行

#### 1-3. 確定仕様

##### 画面操作の挙動

| 順 | 操作・状態 | 画面の動き |
|---|---|---|
| 1 | 発行画面（`#/`）を開く | 上から、バナー（501×146px）、見出し「チケット発行」、説明文、画像の選択、「発行する」ボタン、（エラーの枠、）補足事項が出る。画像を選ぶまでボタンは押せない |
| 2 | 画像を選ぶ | iOS: 選択欄が 1 つ（写真・カメラ・ファイルを iOS のメニューから選ぶ）。Android: 「画像を選ぶ」「カメラを起動」の 2 つのボタンが縦に並ぶ（Android 14 以降は選択画面でカメラを選べないため）。選んだファイルの名前と大きさが出る |
| 3 | 4MB を超える画像を選んだ | 「画像を縮小しています…」と出して縮め（この間は押せない）、縮んだら「縮小しました（11.9MB → 3.4MB）」と出す。縮めても収まらない・縮められない（Android の HEIC など）ときは、ボタンの下に「画像のサイズが大きすぎます（4MB まで）」 |
| 4 | 対応していない形式を選んだ | ボタンの下に「この形式の画像には対応していません（JPEG / PNG / HEIC / HEIF / AVIF / WebP）」。押せない |
| 5 | 「発行する」を押す | ボタンが「送信中…」になり、押せなくなる（二重発行の防止） |
| 6 | 発行できた | チケット画面（`#/tickets/{コード}?sig={署名}`）に移る（戻るボタンで発行の直後に戻らないよう、履歴を置き換える） |
| 7 | 発行できなかった | ボタンの下のエラーの枠に文言を出し、もう一度押せる。別の画像を選ぶと消える |

エラーの文言（API の結果）:

| 結果 | 文言 |
|---|---|
| 解析の判定が `REJECT` | この証明書の画像ではチケットを発行できません |
| 解析の判定が `RETRY` | 画像をうまく確認できませんでした。明るい場所で、証明書全体が写るように撮り直してください |
| 解析サーバーにつながらない・時間切れ | ただいま混み合っています。時間をおいてお試しください |
| API の大きさ・形式のエラー | 画像のサイズが大きすぎます / この形式の画像には対応していません（…） |
| そのほか（通信の失敗、30 秒のタイムアウトなど） | 発行できませんでした。もう一度お試しください |

API（チケット付与 API）:

- `POST /v1/tickets`（`multipart/form-data` の `image`、`Accept: application/json`）→ `201 { ticketCode, issuedAt, sig, qrUrl }`
- エラーは JSON（`{ "error": { "code", "message" } }`）: 413 `PAYLOAD_TOO_LARGE`、415 `UNSUPPORTED_MEDIA_TYPE`、422 `IMAGE_REJECTED` / `IMAGE_RETRY`、502 `ANALYSIS_UPSTREAM_ERROR`、504 `ANALYSIS_TIMEOUT`

#### 1-4-2. 実装方式

- **画面 → API**: SPA が `fetch` で `FormData`（`image`）を `POST /v1/tickets` に送る（`Accept: application/json`）。同じオリジンの相対パスなので、CloudFront の `/v1/*` を通って API Gateway に届く（CORS は要らない）
- **API Gateway**: 発行の Lambda（`tickets`）を呼ぶ
- **Lambda（`tickets`）**: 画像の大きさ（4MiB 以下）と形式を確かめ、解析サーバーに画像をそのまま送る。`PASS` ならチケットコードを作り、署名して、QR 画像の URL（`{公開 URL}/v1/tickets/{コード}/qr?sig={署名}`）と一緒に返す。署名の salt とコードの固定文字列は、起動時に Parameter Store から読む
- **画像の縮小**: 画面で画像を選んだとき、上限を超えていれば Compressor.js（ブラウザの canvas で縮めて JPEG にする）で縮める。上限以下の写真は加工せずに送る
- **検証**: 画面は、`config.json` と API の応答を valibot で確かめる（形が違えば「予期しない応答」として扱う）
- **古いブラウザへの対応**: ビルドの出力を iOS 13（Safari 13）・Chrome 80 に合わせる（新しい構文を変換する）。CSS は Tailwind CSS 3.4。足りない組み込みの関数は core-js で補う

#### 1-4-2. 実装方式

- **URL だけから描く**: チケット画面は、URL のコードと署名を valibot で確かめ、`<img src="/v1/tickets/{コード}/qr?sig={署名}">` で QR を読み込む。発行の結果は画面に保存しない（再読み込みや共有に強く、再発行もされない）
- **署名で確かめる**: QR 画像 API は、この API が発行したコード（署名が合うもの）にだけ QR を返す。署名が合わない URL は 403 になり、画面は `<img>` の読み込みの失敗として「無効なチケット URL です」を出す
- **別の Lambda 関数**: QR 画像は、発行とは別の Lambda 関数（`get-qr`。VPC の外）で返す。画像の表示が、発行（解析サーバーを呼ぶ）の同時実行数の上限で止まらないようにするため
- **表示の調整**: QR の画像には周りに白い余白があるので、見出しとの間の余白を小さくしている

## 3. 設計上の判断

| 判断 | 理由 |
|---|---|
| チケットを保存せず、署名で確かめる | データベースを持たずに済み、API を増やしても状態を共有しなくてよい。QR の URL は、署名が合うものだけが有効 |
| 発行と QR 画像の Lambda 関数を分ける | QR 画像の表示を、発行（解析サーバーを呼ぶ）の上限から切り離す。VPC に入れるのは解析サーバーを呼ぶ発行の関数だけでよい |
| すべて CloudFront で受け、`/v1/*` を API に振り分ける | 画面と API が同じオリジンになり、CORS が要らず、CSP も単純になる |
| 画像の上限を 4MiB にする | Lambda が受け取れるのは 6MB までで、API Gateway が画像を base64 にすると約 1.33 倍になるため |
| 上限を超えた写真だけを縮める | 上限以下の写真は加工せずに送り、今の解析の結果を変えない。縮めるのは、そのままでは送れない写真だけ |
| 縮めるのは画面（ブラウザ）で行う | API に届く前に大きさを抑える（API の上限を超えないため）。ブラウザで画像を縮める方法は canvas だけで、Compressor.js はその手間（写真の向き、大きくなったら元を返すなど）を引き受ける |
| 古いブラウザへの対応（Tailwind CSS 3.4、valibot、core-js、ビルドの出力先） | Tailwind CSS 4 は iOS 15.3 以前でスタイルが付かない。zod 4 は読み込み時に `BigInt`（iOS 14 から）を使い、iOS 13 で画面が真っ白になる。ビルドは構文しか変換しないので、足りない関数は core-js で補う |
| エラーは「発行する」ボタンの下の 1 か所に出す | 送る前の問題と API のエラーを同じ場所にそろえ、見落としを防ぐ |
| チケットコードと発行日時を画面に出さない | 利用者に必要なのは QR だけ。コードは QR とテスト用の属性にだけ持つ |
