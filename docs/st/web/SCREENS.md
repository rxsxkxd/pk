# 画面の構成要素（画像アップロード画面・QR 表示画面）

各画面の要素と、その機能。画面遷移方式（`page`。メインの方式）の SPA について、2026-10-13 時点の実装で書く。設計の詳しい理由は [DESIGN.md](DESIGN.md) 3章。

- 画像アップロード画面: `#/`（`src/modes/page/GrantPage.vue`）
- QR 表示画面: `#/tickets/{code}?sig={sig}`（`src/modes/page/TicketPage.vue`）
- 要素は画面の上から順に書く。条件付きの要素は（）に出る条件を書く

## Android 版

### 画像アップロード画面

| 要素 | 機能 |
|---|---|
| バナー | 画面の先頭に出す 501×146px の画像（今は仮）。画面の幅に合わせて縮む |
| 見出し「チケット発行」 | 画面の名前 |
| 説明文 | 画像の選び方と、発行すると QR が出ることを案内する（約 100 文字）。3つの発行方式で共通の部品（`GrantDescription`） |
| 「画像を選ぶ」ボタン（「カメラを起動」と縦に並ぶ） | 端末の写真から証明書の画像を選ぶ（Android 14 以降はフォトピッカーが開く）。対応形式は JPEG / PNG / HEIC / HEIF / AVIF / WebP |
| 「カメラを起動」ボタン | 背面のカメラを直接起動し、その場で撮った写真を使う（フォトピッカーではカメラを選べないため、別のボタンにしている） |
| ファイル名と大きさ（画像を選んだとき） | 選んだ画像のファイル名と大きさを出す。プレビューは出さない |
| 「画像を縮小しています…」（選んだ画像が上限の 4MB を超えたとき） | 送れる大きさに縮めている間に出す。この間は送れない |
| 「縮小しました（11.9MB → 3.4MB）」（縮められたとき） | 縮める前と後の大きさを出す。送るのは縮めた画像（JPEG） |
| 画像の問題（選んだ画像に問題があるとき） | 送る前に分かる問題を赤字で出す（縮めても 4MB に収まらない・縮められない、対応していない形式）。この間は送れない |
| 「発行する」ボタン | 画像を API に送ってチケットを発行し、成功したら QR 表示画面に移る。使える画像を選ぶまでと、送信中は押せない |
| ボタンの「送信中…」（送信中） | 送っている間、ボタンの文字が変わる。二重に発行されないよう押せなくなる |
| エラーの枠（発行に失敗したとき） | API のエラーを文言にして出す（解析で NG、撮り直しが必要、混雑、通信の失敗など）。もう一度押して送り直せる |

### QR 表示画面

| 要素 | 機能 |
|---|---|
| バナー | 画像アップロード画面と同じ |
| 見出し「チケット」 | 画面の名前 |
| QR コード | チケットの QR。URL の `code` と `sig` から QR 画像 API の画像を読み込む。リロードしても同じ QR が出て、再発行はされない |
| 「無効なチケット URL です」（URL が正しくないとき） | URL の形が違う、または署名が合わず QR を読み込めないときに、QR の代わりに出す |
| チケットの使い方（QR が出ているとき） | 入場のときに QR を見せること、画面を明るくすると読み取りやすいこと、URL を保存すれば同じ QR を出せることを案内する |
| 「別の証明書の画像で発行する」ボタン | 選んだ画像を消して、画像アップロード画面に戻る。見た目は「発行する」ボタンと同じ（中身は画面を移るリンク） |

- iPhone の写真は HEIC のまま送られることを見込んでいる（実機で要確認）。HEIC は JPEG より小さく、4MB を超えにくい

## ほかの発行方式との違い

- その場表示方式（`inline`）: QR 表示画面に移らず、画像アップロード画面の下に QR を出す。リロードすると QR は消える
- フォーム送信方式（`form`）: 画像アップロード画面は、選択欄と「発行する」ボタンだけのフォーム。QR は API のチケット表示ページに出る（SPA の画面ではない）
- どちらも、画面の上から順の要素（バナー、見出し、説明文、画像の選択、ボタン）は画面遷移方式と同じ。ただし、フォーム送信方式の選択欄は Android でも1つで、送る前の確認もしない

## 発行方式と SPA の関係

3つの発行方式は、どれも同じ SPA（Vue、hash モードのルート）をビルドしたもの（ビルドのときに1つを選ぶ。DESIGN.md 4.1）。違うのは、API をどう呼び、結果をどこに出すか。

| 方式 | 画像アップロード画面 | QR を出す画面 |
|---|---|---|
| page（画面遷移方式） | SPA | SPA（`#/tickets/…`） |
| inline（その場表示方式） | SPA | SPA（同じ画面の下） |
| form（フォーム送信方式） | SPA | **SPA ではない**（ブラウザがフォームを API に直接送り、API が返す HTML のチケット表示ページに移る） |

- page は、最後まで SPA の中で完結する。発行は `fetch` で API を呼んで JSON（コードと署名）を受け取り、ページを読み込み直さずに QR 表示画面に移る（vue-router の `replace`）。QR は `<img>` で QR 画像 API から読み込む
- SPA の外に出るのは form だけ。そのため form の QR の画面には、SPA の要素（バナーなど）は出ない
